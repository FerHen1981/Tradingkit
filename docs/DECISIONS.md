- 2026-08-19 · inbox-6 (D-nummer aangevraagd) · **Portefeuille-selectie: decorrelatie wordt gemeten, niet aangenomen** · de mill beoordeelt elke kandidaat op zichzelf (PF) en kan daarom geen ongecorreleerde set opleveren — het vindt dezelfde edge N keer onder andere namen. `backtest/portfolio.py` selecteert nu een SET uit de OOS-overlevers op drie gemeten assen: dagelijkse rendementscorrelatie (**alleen positieve correlatie is een veto** — elk prop-account heeft een eigen drawdown-buffer, dus verliezen op tegengestelde dagen is juist gewenst), **gedeelde slechte dagen** (Jaccard op dagen met verlies ≥20% van de buffer — voor een vloot is gelijktijdige drawdown de doodsoorzaak, en gewone correlatie onderschat precies die staart) en regime-overlap (cosinus op `edge_by_regime`). Elke afwijzing noemt de tegenhanger die hij dupliceert. `verify.py` legt daarvoor nu per kandidaat de dagelijkse P&L-reeks én de regime-attributie vast (OOS-regimelabels één keer in de parent berekend, workers attribueren hun eigen trades). Advies dat hieraan vooraf ging: **niet eerst het indicator-universum uitbreiden** — classic/SMC/price-action zitten al in de 16 gewirede groepen, en meer indicatoren mét per-kandidaat-PF-selectie levert meer klonen op, geen spreiding. · raakt: lab-funnel, fleet-samenstelling
